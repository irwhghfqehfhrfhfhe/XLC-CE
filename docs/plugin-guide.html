一、给你的插件做一个设置页

点「打开」之后看到的那个窗口，就是插件包里的 panel.html。它最常见的用途，是这个插件自己的设置页 —— 让你写的插件记住用户的选择：怎么称呼他、用哪种主题、保存时要不要弹提示。这些设置存在插件自己的目录里， 跟启动器设置页互不影响，卸载插件时一起删掉。

先把概念分清：「插件自己的设置」用 storage 存，几行代码就够； 「让插件去改启动器设置」是另一项能力，需要 control 权限 —— 那是进阶内容，放在本章最后一段。

第一步：清单里申请两项权限

{
  "id": "my-panel",
  "name": "我的插件",
  "version": "1.0.0",
  "entry": "panel.html",
  "permissions": ["storage", "notify"]
}

storage 用来存设置；notify 用来在保存后弹一条提示（不申请也能保存，只是少个反馈）。 导入时这两项都会列出来，用户可以取消勾选 —— 被取消了你调用时会被直接拒绝，错误信息里会写明原因。

第二步：默认值写在一处

const DEFAULTS = { nick: '玩家', theme: 'auto', toastOnSave: true };
const KEY = 'settings';

读出来的时候用 Object.assign({}, DEFAULTS, saved || {}) 合并：老用户存的那份可能没有你后加的选项， 缺哪个补哪个，不用写迁移代码。

第三步：读回来 → 填表单 → 存回去

// 读：没有存过就返回 null
const saved = await host('storage.get', { key: KEY });
const settings = Object.assign({}, DEFAULTS, saved || {});

// 画：把值填进表单
document.querySelector('#nick').value = settings.nick;

// 存：写回插件自己的目录（返回当前总字节数）
await host('storage.set', { key: KEY, value: next });

// 恢复默认：删掉那份，下次打开又是默认值
await host('storage.remove', { key: KEY });

host() 只是把桥包一层，四行就够 —— 失败时抛错，成功时直接给你 data：

async function host(method, params) {
  const r = await window.xlcPlugin.call(method, params);
  if (!r || !r.ok) throw new Error((r && r.error) || '调用被拒绝');
  return r.data;
}

示例插件 docs/examples/hello-xlc 里的 panel.js 可以直接拿走当模板。

关键一句：设置必须落在 storage 里。面板窗口关掉，它的 JS 进程就没了 —— 只存在变量里，重开面板就回到默认值。

几个容易踩的坑

坑怎么绕
值只放在内存变量里每次改动都 storage.set，或至少在「保存」按钮里落一次
存太多一个插件总共 64 KB；存偏好够用，别拿来塞图片或大段日志
主题写死成深色先 await api.info() 拿 theme，再往 body 上挂 .light；用户自己选了主题就按他的来
一上来十几个选项没人会看。先给 3～5 个真正影响体验的，剩下的留到以后加（合并默认值的好处就在这儿）

那「让插件改启动器设置」呢？

这是另一项权限：清单里声明 control，被授权后可以调 config.schema / config.get / config.set / config.reset。导入时它会以琥珀色的 「高权限 / 慎给」单独列出来，用户可以取消勾选。

它有一条写死在启动器代码里的红线：不能把任何东西藏起来 —— 改不了插件开关、改不了「公告已读」、 关不掉更新提示，也不能把启动器窗口设成「隐藏」。每次改动都会落盘、写日志、刷新界面， 并在右下角提示「插件「某某」改动了设置」。

绝大多数插件只需要 storage。要做「一键优化」「批量改参数」这类插件， 再看《插件开发文档》的 §4.3：那里有完整字段表、范围校验和禁区说明。

二、给启动器添加一个页面（page.html）

设置面板是从插件列表里点「打开」才看到的。如果希望插件在启动器里一直有个入口—— 在包里再放一个 page.html，侧栏就会多出一项，点开就是你的页面。

我的插件/
  plugin.json
  panel.html        ← 设置页（可选）
  page.html         ← 页面（固定文件名，放根目录）
  page.js
  Images/
    Logo.png        ← 侧栏入口图标（文件名必须是 Logo.png）
  • 侧栏名字：清单里写 "pageTitle": "我的页面"；不写就显示插件名。
  • 不开新窗口：点侧栏那一项，主窗口内容区直接切过去，跟启动器自带的页面一样。
  • 图片怎么引：全部放 Images 文件夹（或任意子目录），页面里相对路径引用，例如 <img src="Images/pic.png">。
  • 接口和面板一样：window.xlcPlugin.info() / call()，权限还是清单声明 + 用户勾选那套。
  • 不想要页面：把 page.html 从包里去掉就行；停用 / 删除插件时，侧栏那项和页面一起消失。
  • 一个插件包只有一个页面；装多个带页面的插件，侧栏就有多项。
和设置页怎么分工：设置页（panel.html）管「插件自己的偏好」，从插件列表打开； 页面（page.html)是给用户天天用的功能界面，常驻侧栏。两个 HTML 共用同一份 storage 数据， 示例插件里页面显示的称呼就是设置页存的。

三、插件到底是什么

说穿了就三样东西：一份说明（告诉启动器你是谁、要用什么能力）、一个网页（插件的界面，也就是你点「打开」之后看到的那个窗口）、一个 ZIP 包（把上面这些装进去，方便导入）。

你不必懂 Electron、不必碰启动器的任何一行代码。面板就是个普通网页 —— 会写 HTML 和 JavaScript 就够了。

四、十分钟做出第一个插件

  1. 建一个空文件夹

    名字随意（例如 my-plugin），这个文件夹里的东西稍后会整个打成一个 ZIP。

  2. 写 plugin.json

    这是插件清单，启动器靠它认识你。新建一个记事本文件，粘贴下面内容，编码选 UTF-8：

    {
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "author": "你的名字",
  "description": "一句话说明这个插件做什么，会显示在插件卡片上。",
  "entry": "panel.html",
  "permissions": ["notify", "storage"],
  "allowedHosts": []
}
    字段必填说明
    id是小写字母开头，只能用字母 / 数字 / - / _。必须唯一，也不能和内置插件（seedmap / server / gamepad）重名
    name是显示名，别超过 24 个字
    version是形如 1.0.0
    entry否面板页面，不写就是「没有界面、只提供后台能力」
    permissions否申请哪些能力，见第六节。声明了也不等于拥有，还要用户导入时勾选
    allowedHosts否要联网就得写，填域名不带 https://，最多 20 个
    author / description / icon / homepage否展示用。图标放 icon.png 并在这里写文件名
    第一次做插件，建议权限只写 notify 和 storage。用户看到「它只要两个小权限」会更愿意装。

  3. 写面板 panel.html

    就是一个普通网页，跟平时写页面没有区别：

    <!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>我的插件</title>
  <link rel="stylesheet" href="panel.css">
</head>
<body>
  <h2>我的插件</h2>
  <p id="who">正在读取插件信息…</p>
  <button id="save">存一个值</button>
  <p id="out"></p>
  <script src="panel.js"></script>
</body>
</html>

  4. 写 panel.js —— 唯一要知道的接口

    面板里只有一个入口：窗口上挂着的 window.xlcPlugin。

    /* 1) 自己的身份信息：插件名、版本、当前主题、哪些权限被批准了 */
const info = await window.xlcPlugin.info();
document.getElementById('who').textContent =
  info.name + ' v' + info.version + ' · 主题 ' + info.theme;

/* 2) 存一个值（需要 storage 权限） */
const r = await window.xlcPlugin.call('storage.set', { key: 'lastSeed', value: '12345' });
if (r.ok) {
  document.getElementById('out').textContent = '已保存，当前共 ' + r.data + ' 字节';
} else {
  document.getElementById('out').textContent = '失败：' + r.error;
}

/* 3) 弹一条提示（需要 notify 权限） */
await window.xlcPlugin.call('notify', { text: '来自我的插件' });
    调用永远不会抛异常。无论成功失败都会回一个 { ok, data?, error? }， 照 ok 分支写就行。不需要自己编请求序号，也不用挂消息监听。

    如果被拒绝了，error 会直接告诉你原因，例如：

    { "ok": false, "error": "「notify」权限未授权（插件清单里申请了，但导入时没有勾选它，可重新导入并允许）" }

  5. 打包成 ZIP

    在资源管理器里进入文件夹、全选里面的文件 → 右键 → 压缩。然后把压缩包改名成 my-plugin.zip。

  6. 导入，然后打开它

    • 启动器 → 侧栏「导入」→「导入插件」→ 选你那个 ZIP。
    • 启动器会校验包，然后把插件申请的能力列出来，勾掉你不放心的项，确认安装。
    • 去「插件」页，卡片已经在了 —— 点「打开」。

    插件面板会在一个独立窗口里打开，标题是你的插件名。改代码之后重新打一次包、再导入一次即可（同一个 id 会覆盖安装，启用状态和存过的数据都保留）。

五、面板能做什么、不能做什么

你的面板运行在一个独立窗口里，跟启动器之间没有任何「亲属关系」。这不是限制你，而是让用户放心装你的插件 —— 正因为碰不到启动器，你说「我只存个数据」才是可信的。

你能做的事说明
写任意 HTML / CSS / JS面板就是个网页，界面完全由你决定，不用迁就启动器的样式
读自己的身份与主题info() 能拿到插件名、版本、当前是深色还是浅色主题，让面板跟启动器保持一致
用被批准的能力按第七节那张表调用，每一条都要在清单里声明、并被用户勾选
读写启动器设置需要 control 权限（第一节末尾有说明，字段见开发文档 §4.3）。不能把东西藏起来，且每次改动用户都会看到
你做不到的事原因
读启动器源码 / 调它的内部接口面板窗口里没有 window.lmc，和启动器窗口没有任何关系
用 require、直接读写文件面板里没有 Node 环境；要存数据走 storage，只落在插件自己的目录
直接 fetch 联网网络请求被整个切断，只能走 http 权限 + 白名单域名
引用 CDN 上的 js / css / 字体面板必须自包含，脚本样式只允许来自你自己的包里
把启动器「改瞎」或者藏东西改设置可以，但插件开关、公告已读、更新提示、窗口可见性这一类改不了 —— 启动器主线代码里就拦着，不是靠自觉

六、能申请的权限

权限含义
notify在启动器里弹一条提示（右下角）
storage在插件自己的目录里存数据（键值 JSON，上限 64 KB）
launcher读取启动器基础信息（版本号、游戏目录、下载源设置）
versions读取本机已安装的版本 / 实例列表
control读取并修改启动器设置（下载源 / 内存 / Java / 主题 / 实例设置…）。高危权限，导入时单独标红；改不了「一改就等于把东西藏起来」的项，详见第一节
openExternal用系统默认浏览器打开 allowedHosts 里声明过的网站
http以 GET 方式访问 allowedHosts 里声明过的网站（单次上限 1 MB，每分钟最多 30 次）
用户可以在导入时取消勾选任何一项。没勾的能力，调用时会返回 ok:false 并说明原因 —— 所以面板里最好对「权限缺失」友好一点，别让用户看到一片空白。

七、接口表

调用格式：await window.xlcPlugin.call(method, params)。

method参数返回需要权限
notify{ text, kind? }truenotify
storage.get{ key }存过的值，没有则 nullstorage
storage.set{ key, value }当前数据总字节数storage
storage.remove{ key }truestorage
launcher.info—{ version, gameDir, source, theme }launcher（有 control 也可用）
versions.list—[{ id, loader, inherits }]versions（有 control 也可用）
config.schema—{ apiVersion, appVersion, items, never }control
config.get{ key? }设置值；不传 = 整份control
config.set{ key, value } 或 { items }{ changed, keys, labels }control
config.reset{ key }同上control
openExternal{ url }trueopenExternal + 域名在白名单
http.get{ url }{ status, text }http + 域名在白名单

没列出的 method 一律被拒绝 —— 而且报错信息里会带上可用的清单，方便你对着改。另外 notify 有 0.6 秒节流、openExternal 2 秒、http.get 每分钟 30 次，被限流时同样返回 ok:false。

八、包里能放什么

plugin.json      必需   插件清单
panel.html       可选   插件面板（清单里的 entry 指向它）
panel.js / css   可选   同目录的资源，面板里用相对路径引用
page.html        可选   侧栏页面（固定文件名、放根目录，见第二节）
page.js / css    可选   页面的资源
Images/Logo.png  可选   侧栏入口图标（文件名必须是 Logo.png，放 Images 文件夹里）
icon.png         可选   插件卡片上的图标
README.md        可选   说明文件
项目限制
允许的文件类型html htm js mjs css json txt md png jpg jpeg gif webp svg ico woff woff2 mp3 ogg wav
被拒绝的文件exe / dll / jar / bat 等可执行文件，出现即拒绝安装
体积压缩包 ≤ 8 MB、单文件解压后 ≤ 2 MB、解压后总计 ≤ 20 MB、文件数 ≤ 600

九、调试

  • 面板是标准 Chromium 窗口：右键 → 检查（或按 F12）就能打开开发者工具，看 console、网络、DOM 都在那里。
  • 面板和启动器是两个独立窗口，所以你面板里的 console.log 只会出现在面板自己的开发者工具里，别去启动器那边找。
  • 想看看自己存了什么：插件卡片下方「打开目录」，.xlc-data.json 就是 storage 的内容（这是点文件，你在面板里读不到它，只能走接口）。
  • 导入失败时启动器会直接提示原因（缺清单、JSON 语法错、路径非法、文件类型不允许……），照着改包就行。

十、常见错误对照

启动器提示原因
缺少 plugin.json压缩时多套了一层文件夹，或清单文件名写错了
plugin.json 不是合法的 JSON写了注释、用了中文引号、或少了逗号
plugin.json 内容不合法id 有大写或特殊字符、name 为空、version 不是 1.0.0 的形式、entry 不是 .html
不允许放这种文件包里混进了 exe / dll / jar 等可执行文件
包里有非法路径压缩包条目里带了 ../ 或绝对路径（正常压缩不会出现）
清单里的面板文件不存在entry 写的文件名与包内实际文件不一致（注意大小写）
「xxx」权限未授权导入时没勾选该权限 —— 重新导入并勾上即可

十一、照着一个能跑的示例改

官方提供了一份示例插件（docs/examples/hello-xlc）：设置页 + 侧栏页面两个网页、九个文件，几个偏好项， 打开时从 storage 读回来、点保存写回去、还能恢复默认，顶部顺带用 launcher.info 显示启动器版本。 它的结构与本教程完全一致，改掉名字和界面就是你自己的插件。

更细的字段规则、接口行为与安全说明，见配套的完整开发文档；示例包也可以直接在插件页导入跑起来看。

给想认真做插件的朋友一句话：把权限申请得越少，用户越愿意装。 一个只要 storage 的小工具，比一个开口就要「联网 + 读你所有版本」的插件更容易被人信任 —— 这也是这套权限机制存在的意义。
